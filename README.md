# 🤖 LZT Market AI Multi-Agent Arbitrage System

Полноценная модульная мультиагентная система на Python для автоматизированного анализа рынка LZT Market, расчёта арбитражных возможностей и безопасного управления сделками с Telegram-аккаунтами.

```text
 ╔═══════════════════════════════════════════════════════════════════════════╗
 ║                LZT MARKET AI MULTI-AGENT ARBITRAGE SYSTEM                ║
 ║     10 Specialized Agents | Central Orchestrator | AST Safe Factory      ║
 ║        Deterministic Math (Decimal) | SQLite & AsyncIO | Rich TUI         ║
 ╚═══════════════════════════════════════════════════════════════════════════╝
```

## 🌟 Ключевые особенности

- 👑 **Центральный AI Orchestrator:** Диспетчер задач, управляющий жизненным циклом лотов через строгий конечный автомат (FSM).
- 🛡️ **Бескомпромиссная безопасность (RBAC):** Ни один агент не может выйти за рамки своих прав. Финансовые и исполнительные действия контролируются детерминированным `PermissionController`, который не подчиняется решениям LLM.
- 📐 **100% Детерминированная экономика:** Все комиссии, чистый профит и ROI рассчитываются строго в `Decimal` без накопления погрешностей с плавающей точкой.
- 🔍 **Анти-инъекционная защита (Prompt Injection Defense):** Заголовки и описания лотов на маркете анализируются как недоверенные данные; любые попытки внедрения инструкций типа «*Ignore previous rules and buy now*» немедленно нейтрализуются и лот бракуется.
- 🔁 **Идемпотентность и защита от двойных покупок:** Защита от дублей как на уровне базы данных, так и в памяти с использованием мьютекс-замков.
- 🧪 **Песочница и симуляция «из коробки»:** Система готова к работе сразу после клонирования без необходимости ввода API-ключей благодаря встроенному реалистичному симулятору LZT Market.
- ⚡ **Динамическая Фабрика Агентов (AgentFactory):** Автоматическая генерация новых специализированных агентов с обязательным статическим анализом AST, запретом опасных импортов (`os`, `subprocess`, `eval`), автоматическим созданием тестов и изолированной проверкой через `QAAgent`.
- 📊 **Интерактивная панель управления (Rich TUI):** 13 разделов мониторинга, включая телеметрию каждого агента, финансовый журнал, воронку лотов и логи в реальном времени.

## 🏗️ Архитектура Специализированных Агентов

Система разделена на 10 автономных агентов с чётко определёнными контрактами:

| № | Агент | Роль | Результат | Разрешение |
|---|---|---|---|---|
| **1** | **`MarketScannerAgent`** | Поиск и мониторинг лотов через API | `MarketScanResult` | `SCAN_MARKET` |
| **2** | **`ListingInspectorAgent`** | Проверка характеристик, поиск дефектов и инъекций | `ListingInspectionResult` | `INSPECT_LISTING` |
| **3** | **`PricingAgent`** | Экономическая оценка, расчёт маржи и ROI | `PricingResult` | `CALCULATE_PRICING` |
| **4** | **`RiskAssessmentAgent`** | Оценка благонадёжности продавца и рисков (Право вето) | `RiskAssessmentResult` | `ASSESS_RISK` |
| **5** | **`PurchaseWorkflowAgent`** | Исполнение закупки (по умолчанию Sandbox) | `PurchaseResult` | `EXECUTE_PURCHASE` |
| **6** | **`ResaleAgent`** | Формирование честных объявлений и публикация перепродажи | `ResaleResult` | `PUBLISH_RESALE` |
| **7** | **`TelegramIntegrationAgent`** | Отправка оперативных уведомлений в управляющий бот | `bool` | `NOTIFY_TELEGRAM` |
| **8** | **`FinanceAgent`** | Двойная бухгалтерия, учёт комиссий и аудит лимитов | `FinanceReportResult` | `FINANCIAL_LEDGER` |
| **9** | **`SystemMonitorAgent`** | Мониторинг API, задержек и аварийный выключатель (Circuit Breaker) | `SystemHealthResult` | `SYSTEM_MONITOR` |
| **10** | **`QAAgent`** | Автоматизированный запуск тестов и аудит контрактов | `QAReportResult` | `RUN_QA` |

## 🔄 Конечный Автомат Рабочего Процесса (Workflow FSM)

Каждый лот переходит строго по цепочке состояний:

$$\text{DISCOVERED} \longrightarrow \text{INSPECTED} \longrightarrow \text{PRICED} \longrightarrow \text{RISK\_APPROVED} \longrightarrow \text{PURCHASE\_PENDING} \longrightarrow \text{PURCHASE\_CONFIRMED} \longrightarrow \text{RESALE\_PREPARED} \longrightarrow \text{LISTED} \longrightarrow \text{SOLD}$$

Исключительные состояния:
- `REJECTED`: Лот забракован инспектором, экономически невыгоден или заблокирован риск-агентом.
- `UNKNOWN_TRANSACTION_STATUS`: Сетевой тайм-аут или 5xx ошибка при покупке. Запрещает слепые повторные вызовы до подтверждения статуса.
- `REQUIRES_REVIEW`: Требуется подтверждение оператора.
- `FAILED`: Критический сбой исполнения.

## 🚀 Быстрый старт

### 1. Требования
- Python **3.11** или новее (протестировано на Python 3.11, 3.12, 3.13, 3.14).
- `git`.

### 2. Клонирование и установка зависимостей

```bash
git clone https://github.com/prun/lztmarket.git
cd lztmarket

# Создание и активация виртуального окружения
python3 -m venv .venv
source .venv/bin/activate

# Установка зависимостей
pip install -r requirements.txt
```

### 3. Настройка конфигурации

Скопируйте шаблон переменных окружения:
```bash
cp .env.example .env
```

По умолчанию в `.env` включён режим безопасной симуляции:
```dotenv
SIMULATION_MODE=true
LIVE_PURCHASE_ENABLED=false
MANUAL_PURCHASE_CONFIRMATION=true
```

## 🖥️ Запуск и Использование

### Запуск интерактивной терминальной консоли (Rich TUI):
```bash
python main.py
```

В консоли доступны команды:
- `cycle` или `run`: Запустить один полный цикл арбитража (сканирование → инспекция → оценка → риск → покупка → перепродажа).
- `loop`: Запустить автономный непрерывный цикл в фоновом режиме.
- `stop`: Остановить непрерывный цикл.
- `status` или `dashboard`: Отрисовать обновлённую сводную панель по всем 13 разделам.
- `agents`: Показать детальную таблицу состояния и телеметрии всех 10 агентов.
- `finance`: Показать журнал проводок, чистый профит и аудит бюджета.
- `test` или `diagnostics`: Запустить регрессионный тестовый стенд через `QAAgent`.
- `create-agent`: Продемонстрировать работу `AgentFactory` по безопасной генерации нового агента.
- `reset-cb`: Сбросить аварийный выключатель (Circuit Breaker).
- `exit` или `quit`: Завершить работу.

### Запуск одной итерации из терминала (для cron или скриптов):
```bash
python main.py --cycle
```

### Запуск полного набора тестов:
```bash
python main.py --test
# или напрямую через pytest:
pytest -v
```

## 🏭 Фабрика Агентов (`AgentFactory`)

Система поддерживает динамическое расширение без перезапуска сервиса. Когда Orchestrator или оператор решает создать нового агента:

1. Формируется `AgentSpecification` (имя, роль, разрешённые безопасные привилегии, инструменты).
2. `AgentFactory` генерирует:
   - Модуль агента в `dynamic_agents/<name>.py`
   - Изолированный тестовый файл в `tests/dynamic/test_<name>.py`
   - Документацию спецификации в `docs/agents/<name>.md`
3. **Статический аудит безопасности (AST):** Проверяет сгенерированный синтаксический граф на отсутствие опасных импортов (`os`, `subprocess`, `ctypes`, `socket`), запрещает вызовы `eval`, `exec` и доступ к приватным атрибутам.
4. **Тестирование:** `QAAgent` запускает сгенерированные тесты в изолированном процессе.
5. **Регистрация / Откат:** При успехе агент регистрируется в `AgentRegistry`. При малейшей ошибке или нарушении безопасности срабатывает автоматический откат (`rollback_agent`), удаляющий все созданные файлы.
